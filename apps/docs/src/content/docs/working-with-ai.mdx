# Working with AI

**UI Kit** gives your AI coding agent the components and rules it needs to build with UI Kit correctly, matched to the version your app uses. One command sets it up.

> [!NOTE]
>
> AI support is in preview. We're expanding it with each release, and your feedback shapes what comes next.

## How it works

Once your project is set up, your agent has:

- **Design rules**: what applies to every screen, such as using design tokens, labeling form controls and protecting users from destructive actions.
- **Component guidance**: each component's props, what each variant is for, how its states behave and what it needs to be accessible.
- **Theme tokens**: each token's value in light and dark mode and what it is for, so your agent picks a token by its meaning.
- **Lint**: a check of the code your agent writes against the design rules, which it runs and fixes as it goes.

All of it comes from the **UI Kit** packages installed in your app; your project only keeps a pointer and a little configuration.

If your agent reads documentation sites, it can also use this site's [llms.txt](/llms.txt).

## Set up

Paste this into your agent:

```text
Set up HV UI Kit for AI agents in this project:
1. Install the tools: npm install --save-dev @pentaho/uikit-tools
2. Run: npx --no-install uikit-tools init
3. Read the HV UI Kit design rules that AGENTS.md now points to and summarize them.
```

To do it yourself, install the tools and run `init`:

```sh npm2yarn
npm i -D @pentaho/uikit-tools
```

```sh
npx --no-install uikit-tools init
```

`init` sets up your project for Claude Code and GitHub Copilot by default:

| File        | What `init` adds                                                                                                                                                |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AGENTS.md` | A short UI Kit block that points your agent to the design rules in your installed UI Kit tools. The rest of the file stays yours.                               |
| `CLAUDE.md` | An import of `AGENTS.md`, so Claude Code reads the same instructions.                                                                                           |
| `.claude/`  | For Claude Code: a hook that lints the project before it finishes, the read-only lookups and screenshots allowed without asking, and the Pentaho plugin skills. |

Choose the agents with `--agents`: `claude`, `copilot`, `cursor`, `codex`, `gemini`, or `all`. Add `--mcp` for the `hv-uikit` MCP server in each agent's configuration (`.mcp.json`, `.vscode/mcp.json`…), and `--figma` for the skills for Figma screens and design reviews. Commit these files so your team shares the setup, then start a new agent session. Running `init` again is safe: it only rewrites its own block and entries. For the Pentaho plugin skills, see [Pentaho plugins](/app-shell/pentaho-plugins#with-a-coding-agent).

## Check your setup

Ask your agent:

```text
Answer from the HV UI Kit design rules and uikit-tools lookups, not from memory:
1. Which HvButton variant should a form's main action use?
2. How do you show a number in an HvBadge?
3. How should an HvDialog show its title?
```

A working setup answers: `primary`, one per form; set `showCount`; with `HvDialogTitle`, not plain text. If your agent answers from memory or invents props, check the setup and restart the session.

## Command line and MCP

The `hv-uikit` MCP server gives your agent the same lookups as the `uikit-tools` command line, with the same answers. Your agent calls the MCP tools on its own; you, your scripts, CI and agents without MCP use the command line, through `npx --no-install` so it runs the version installed in your project and never downloads another.

| Task                                     | Command line                       | MCP tool          |
| ---------------------------------------- | ---------------------------------- | ----------------- |
| Set up your project                      | `uikit-tools init [folder]`        | —                 |
| List the components                      | `uikit-tools components`           | `list_components` |
| Look up a component's guidance and props | `uikit-tools info <components...>` | `get_component`   |
| List the design rules                    | `uikit-tools rules`                | `list_rules`      |
| Read a design rule                       | `uikit-tools rule <id>`            | `get_rule`        |
| Find a token by what it's for            | `uikit-tools tokens <word>`        | `find_tokens`     |
| Check code against the design rules      | `uikit-tools lint [paths]`         | `lint`            |
| Start the MCP server                     | `uikit-tools mcp`                  | —                 |

The MCP server runs locally, only reads UI Kit's data and makes no network calls. Run `npx --no-install uikit-tools --help` for every option.

### Look things up

```sh
npx --no-install uikit-tools info HvDialog
npx --no-install uikit-tools rule tokens/colors
```

These print exactly what your agent gets from `get_component` and `get_rule`.

### Lint your code

`npx --no-install uikit-tools lint src` checks your code against the design rules in any project, with no setup. Your agent runs it through the `lint` MCP tool, and Claude Code before it finishes, through the hook `init` adds.

To see the findings in your editor and CI too, add the UI Kit preset after your other oxlint presets (apps created with `uikit-cli create` use oxlint). It needs oxlint 1.63 or later:

```json
{
  "extends": [
    "./node_modules/@pentaho/uikit-config/oxlint/strict.json",
    "./node_modules/@pentaho/uikit-tools/oxlint.json"
  ]
}
```

It reports native elements that have a **UI Kit** component (`<button>` instead of `HvButton`), hard-coded colors and sizes instead of theme tokens (also in utility classes, such as `p-[24px]` or `text-red-500`), fixed values in inline styles, icon buttons and tags without a name, deprecated components and props, and accessibility problems. Each finding names its rule (`uikit/raw-elements`), the id the design notes and rules cite. With ESLint, add the same rules from `@pentaho/uikit-tools/lint`. Not every design rule can be checked automatically: review the others against the real screen.

## Keep it current

Upgrade the UI Kit packages as usual: the design rules and component guidance come with them, with no need to run `init` again (except to refresh the skills it copies for Claude Code). Restart your agent's MCP server to pick up the change; the command line reads it right away.
